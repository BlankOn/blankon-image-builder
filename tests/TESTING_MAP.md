# Testing scope

- `tests/lib.sh:fixture_init` copies entrypoints into a temporary workspace, creates synthetic sources/configuration, stubs `lb`, mounts, `curl`, and `zsyncmake`, and installs fail-closed Podman, Docker, user-namespace, and sudo guards. `tests/build-iso.sh`, `tests/cache.sh`, and `tests/purge.sh` exercise publication/checksums, local Git clone/branch/commit handling, cache reuse/invalidation, lock contention, and unsafe-path refusal without building a real ISO.
- `tests/podman-wrapper.sh` retains its historical suite name but tests the normal `build-iso` and `purge-iso` entrypoints with fake Podman. Coverage includes local/remote arguments, explicit rootless user mapping, read-only source binds, canonical root/overlap/symlink refusal, safe output and lock paths beneath `BUILD_LOCAL`, shared locks, and purge mount boundaries. Fake curl decodes host-only notification payloads and checks synthetic-token isolation and transport failures. `tests/podman-build-lock.sh` also verifies lock recovery after process termination and inner lock-held dispatch.
- `tests/namespace-dispatch.sh` uses a copied temporary entrypoint and synthetic `.env`, with fake `unshare` and fail-closed Podman/curl commands. `tests/mount-cleanup.sh` stubs mount listings and unmounts to check deepest-first workspace cleanup without unmounting a source tree. These fixtures do not establish live kernel namespace or mount behavior.
- `tests/seccomp-profile.sh` runs offline legacy Moby-profile generator fixtures and static Podman identity/seccomp assertions; host build and purge no longer generate or load the Moby profile. `tests/patch-live-build-sysfs.py` exercises the version-checked image helper patch using temporary input files, not live sysfs mounts.
- `.github/workflows/build-iso.yml` installs and checks rootless Podman, runs all nine task fixture suites, then defines real local and remote ISO builds using `tests/e2e/live-build` on push/PR. The remote bare fixture is staged under `workdir/ci-remote.git` and cloned through `file:///workdir/ci-remote.git` without an external source bind. The manual `gnome` profile uses the upstream mutable `variant-gnome` branch. Neither profile boots an ISO.
- CI uses the production `Dockerfile` through the normal entrypoints without a Compose override or separate Podman workflow. It checks published artifacts, checksums, selected output UID/GID ownership, real package-cache save/restore hashes, and purge preservation for the small profile. `tests/e2e/verify-package-cache.sh` sources `/usr/local/bin/build-iso` inside the Podman image while the host holds the package-cache lock. CI does not verify ISO structure, complete package manifests, or that live-build consumed a restored cache; fixture and static success are not real ISO acceptance evidence.
